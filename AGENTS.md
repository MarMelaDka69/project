# AGENTS.md

## Область действия

Эти инструкции относятся ко всему репозиторию 3D Repository. Стек проекта — Python 3.12, FastAPI, SQLAlchemy, PostgreSQL и HTML/CSS/JavaScript. Запускай команды из корня репозитория.

## Где искать код

- `app/main.py` содержит маршруты и подключает middleware CSRF.
- `app/database.py` создаёт SQLAlchemy engine и фабрику сессий, а `app/models.py` описывает таблицы.
- `app/schemas.py` задаёт схему ответа для модели. Схемы запросов и пользователей сейчас находятся в `app/main.py`.
- `app/auth.py`, `app/security.py` и `app/csrf.py` отвечают за сессии, пароли и CSRF.
- `app/static/static.html` использует HTTP API. При изменении маршрутов или структуры ответа проверь соответствующие вызовы `fetch()`.
- `contracts/openapi.json` — зафиксированный контракт, `tests/` — тесты, `.github/workflows/tests.yml` — конфигурация CI.

## Изменения приложения

- Сохраняй публичный доступ к просмотру каталога, превью и скачиванию. Для записи и загрузки моделей сохраняй серверную проверку авторизации. Для изменяющих запросов учитывай middleware CSRF и передачу `X-CSRF-Token` из браузера.
- Сохраняй `HttpOnly` и настройку `COOKIE_SECURE` у cookie. Для действующего HTTPS-сайта используй `COOKIE_SECURE=true`, для локального HTTP — `false`.
- При изменении схемы БД проверь обновление существующих таблиц и обработку старых строк. Подготовь миграцию для изменений столбцов. `create_all()` применяй для первичной инициализации.
- При работе с загрузками сохраняй доступ к уже записанным путям. Проверяй серверную валидацию, безопасное формирование путей, повторную загрузку и состояние БД и диска при частичном сбое. При выводе пользовательских данных в браузере используй `textContent` или экранирование.
- Выбирай минимальные изменения под задачу. В результате перечисли выполненные проверки и укажи, какие из них остались непроверенными.

## Проверки

- Установи тестовые зависимости из `requirements-dev.txt`. Запусти `python -m pytest -v` с `DATABASE_URL=sqlite://`, тестовым `SESSION_SECRET_KEY` и `COOKIE_SECURE=false`.
- Используй тестовые фикстуры из `tests/conftest.py` и временные каталоги. Новые сценарии проверяй через реальное поведение маршрута, включая ошибки авторизации или валидации, когда они относятся к изменению.
- Если API изменился намеренно, обнови `contracts/openapi.json` через `app.openapi()` по команде из README, проверь diff и запусти тесты. При ненамеренном расхождении выясни причину падения теста.
- Для изменений Docker проверь `docker compose config --quiet`, сборку, доступность каталога и, если затронуто хранилище, сохранность тестовых данных после пересоздания контейнера.

## Git и эксплуатация

- В коммит добавляй файлы задачи. Исключай реальные `.env`, `.env.docker`, архивы и дампы БД, загруженные модели, превью и виртуальные окружения.
- Локальный `compose.yaml` использует собственную БД и локальный порт `8002`. Действующий VPS использует Nginx и службу `3d-repository` с Uvicorn на `127.0.0.1:8001`.
- При обновлении на VPS учитывай владельца рабочего дерева `repo3d`, серверные настройки и права на каталоги данных. Используй команды из README для обновления службы. Операции с рабочей БД, томами и общей конфигурацией Nginx выполняй в рамках запроса на развёртывание.
